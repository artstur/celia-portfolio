Problem Space

When a friend tells me a photo won’t open, their message already tells me what they tried and what they expected. Moving it into a tracker means someone has to describe the same problem a second time.

I built twelve DeepSeek Harness plugins to try a shorter path. Could the conversation where we notice a problem also be where the product starts to change?

01. Three Ways Ideas Travel

A thought I save for later, something a friend says across the table, and a message they send me carry different clues. I wanted to keep those clues when I brought any of them into a question.

One way to ask across all three

If I want to compare a conversation with my notes, I type # and pick the recording and notes I mean. Each plugin keeps its own material. A shared search and read interface finds the items, and the composer reads their current text when I send. I see the sources I picked; I don’t have to paste them into the chat.

02. From a Message to a Release

In the recording, I ask to edit my avatar alongside my name. The iteration plugin recognizes the message as a request. With automatic iteration on, it starts a DSH creation session to try the change. The trail ends in Notes: the release entry for Messages v1.13.1 puts avatar editing in the profile editor.

Mapping the experiments

I built Exploration Atlas to keep track of the decisions behind the plugins. Each stage pairs what I learned with something I can test next.

One distinction I wanted to test was seeing how an agent worked versus changing how it worked. The trajectory viewer shows the steps it took. Verify-before-Finish can ask it to take one more step if it edits a file and tries to finish without checking it.
